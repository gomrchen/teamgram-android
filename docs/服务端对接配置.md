# 服务端对接配置

Android 客户端连接 **自建 Teamgram** 时的网络与 API 配置（非 Telegram 官方数据中心）。

---

## 1. 网关地址（必改）

文件：

```
TMessagesProj/jni/tgnet/ConnectionsManager.cpp
```

在 `ConnectionsManager::initDatacenters()` 中修改（`testBackend` 为 true/false 两处逻辑各有一份，建议 **同步修改**）：

```cpp
datacenter->addAddressAndPort("192.168.1.13", 10443, 0, "");
//                      IP ─────────────┘  端口 ─┘
```

| 场景 | 建议 IP |
|------|---------|
| 手机与服务器同局域网 | 服务器局域网 IP（如 `192.168.1.x`） |
| 公网用户 | 公网 IP 或域名（需自行保证解析稳定） |
| 模拟器连本机后端 | `10.0.2.2`（AVD 访问宿主机）或宿主机局域网 IP |

修改后须 **重新完整编译**（会重新构建 `tgnet` native 库）。

---

## 2. 端口

| 协议 | 端口 | 后端服务 |
|------|------|----------|
| MTProto TCP | **10443** | `gnetway` |
| MTProto TCP | 5222 | `gnetway`（可选） |
| WebSocket | **11443** | `gnetway` |

Android 客户端在 `ConnectionsManager.cpp` 写死 **10443**，一般无需改端口，只需保证服务端 `teamgram/etc/gnetway.yaml` 已监听且防火墙放行。

---

## 3. 后端检查

```bash
# 服务端
bash teamgram/scripts/start.sh
lsof -i :10443 -i :11443

# 从电脑探测
nc -zv <服务器IP> 10443
```

日志：`teamgram/logs/gnetway.log`、`session.log`。

---

## 4. API 凭证

`TMessagesProj/src/main/java/org/telegram/messenger/BuildVars.java`：

```java
public static int APP_ID = 你的api_id;
public static String APP_HASH = "你的api_hash";
```

须与 [Telegram 开发者平台](https://my.telegram.org) 申请的一致；与 iOS / Desktop 自建端建议统一。

---

## 5. 测试登录

- 企业版测试环境常见验证码：**12345**
- 若握手失败：检查 RSA 密钥是否与后端 `server_pkcs1.key` 匹配（见 `teamgram.io/enterprise/docs/更换授权密钥.md`）
- 若超时：优先排查 IP、端口、VPN；**局域网 IP 在蜂窝网络下不可达**

---

## 6. 与其他端对齐

| 客户端 | 配置位置 |
|--------|----------|
| Android | `ConnectionsManager.cpp`（IP/端口）+ `BuildVars.java`（API） |

| Desktop | tdesktop 构建配置 |
| Web | `telegram-tweb/docs/服务端对接配置.md` — `.env` + `dcConfigurator.ts` |
